## 5. Bugs / Issues Found

### 5.1 CRITICAL — fixed
**Late-delivery penalty policy drift.**
`backend/utils/lateDeliveryPenalty.js` had been edited locally to change the
default grace period from **5 days** to **1 day**, but the docstring and unit
tests still described the old 5-day policy. Four unit tests failed as a result.

With your confirmation, the new 1-day-grace policy is now the canonical rule.
The docstring and four test cases were realigned. All callers
(`deliveryPenaltyJob.js`, `Shipment.js`, `shipmentController.js`) use the
default and now behave consistently. **All 886 tests pass.**

### 5.2 MEDIUM — fixed
**Hardcoded admin credentials in `backend/utils/fix_admin.js`.**
The bootstrap script shipped with `phone = '1111'` and `password = 'password123'`.
Refactored to mandate `ADMIN_PHONE` and `ADMIN_PASSWORD` environment variables
and enforce a minimum 8-character password.

### 5.3 LOW — flagged, NOT modified
**Defensive JWT fallback in `backend/middleware/authMiddleware.js`:**

```js
const JWT_SECRET = process.env.JWT_SECRET || 'secret_key';
```

If `JWT_SECRET` is missing, the middleware silently falls back to the string
`'secret_key'`, which would invalidate all real tokens but still let attacker-
forged tokens signed with `'secret_key'` pass. This is not exploitable when
`.env` is configured correctly (the test suite injects a proper value), but for
production hardening you should throw at startup when `JWT_SECRET` is missing.
Left untouched per your instruction "do not modify business logic unless a
critical bug is found".

### 5.4 LOW — flagged, NOT modified
**Default MinIO credentials in `docker-compose.yml`.**
`admin` / `password123` are committed and matching values appear in
`backend/.env.example`. This is fine for **local development only** (and is
explicitly documented as such in `docs/MINIO_S3_SETUP.md`). For any shared
deployment, override `MINIO_ROOT_USER` and `MINIO_ROOT_PASSWORD` in the compose
file and the matching `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` in `.env`.

### 5.5 INFO — no action needed
**Firebase client API key in `lib/firebase_options.dart` and `android/app/google-services.json`** is a *public* identifier (Firebase ships these in shipped APKs). Security is enforced by Firebase Auth rules + backend JWT, not by hiding the key. Officially recommended by Firebase; no change required.
